# Agent script protocol

How an AI assistant delivers code changes to this repository. Read this and
`docs/project-context.md` (the only project reference) before proposing
anything. The owner works from Termux on Android: an Arabic keyboard corrupts
typed English commands and long heredocs break, so every change arrives as one
downloadable bash script.

## 1. Before proposing a change

1. **Read the real tree, not memory.** Work from the uploaded zip or
   `raw.githubusercontent.com/adbrhman/nukhbaa/main/<path>` (pushed commits
   only). Verify every file, function, column and anchor you mention exists.
2. **Trace the whole chain** before judging: route -> use-case -> port ->
   adapter -> database -> `api_client` -> provider -> widget. Count the layers;
   one layer is rarely enough.
3. **Find the guards** a change must pass: `tooling/import_lint`
   (`allowedDependencies`), asserts, CI `--dart-define` plumbing
   (`.github/workflows/*.yml`), generated files (`apps/mobile/lib/l10n/`,
   `*.g.dart`).
4. **Measure before changing.** Numbers first (Supabase usage,
   `pg_stat_statements`, contrast ratios, the installed package source under
   `~/.pub-cache`). A setting not shown to cause the problem is not changed.
5. **One question** when a request has more than one reasonable reading. No
   guessing.

## 2. The script

One bash script per batch, named `NN_short_name.sh`, downloaded to
`/sdcard/Download`.

- **A readable failure:** `set -Eeuo pipefail`; every stage is announced
  with its name (`== [dart analyze --fatal-warnings]`), the whole run is
  copied to a log in `/sdcard/Download/NN_short_name_<time>.log`, and a
  failure prints the name of the stage that failed and the log's path. A
  silent rollback hides the cause.
- **Guards first:** `whoami` is `dev`; `pubspec.yaml` and
  `docs/project-context.md` exist; no uncommitted changes in tracked files
  (`git status --porcelain --untracked-files=no`); the batches this one
  builds on are in the tree (grep for a line they added).
- **Never discard the owner's work.** If the generated l10n output
  (`apps/mobile/lib/l10n/`) has local changes, the script **stops and
  explains** -- it prints the files and the command the owner may run
  himself -- and does not run `git checkout` on it. Only what the script's
  own `flutter` run regenerated is restored at the end, and only because
  l10n was clean at the guard.
- **The patch** is a Python script, ASCII only (non-ASCII text escaped as
  `\uXXXX`), using `str.replace` on literal anchors copied from the file's
  actual text:
  - every anchor must occur **exactly once**, checked for all files before any
    file is written;
  - each edit carries a "done" marker -- text that exists only once the edit
    is in, and that `dart format` cannot rewrap -- and is skipped when the
    marker is present, so a second run is harmless even after formatting;
  - a new file is refused if it already exists with different content; a
    file is deleted only after checking it is the expected file;
  - before embedding, the patch is parsed (`python3 -c "import ast; ..."`):
    an apostrophe inside a quoted string breaks it.
- **Embedding:** the base64 of the patch sits on **one line** in a shell
  variable, `PATCH_B64='...'`, decoded with
  `printf '%s' "$PATCH_B64" | base64 -d`. No heredoc: long heredocs break in
  Termux.
- **Rollback:** `trap rollback ERR`. It unstages the batch's files first (the
  failure may come after `git add`), restores modified and deleted files
  from `HEAD`, deletes the files this batch created (not ones that existed
  before it), and restores l10n regenerated by its own run. The tree ends
  as it was, nothing committed. No `( cd dir && cmd )` subshells: an `ERR`
  inside one fires the rollback twice. Use `cd dir`, run, `cd "$REPO"`.
- **Verification, in order:**
  1. `flutter pub get` only when a pubspec changed;
  2. `dart format` on the touched files only;
  3. `dart analyze --fatal-warnings .`;
  4. `dart run tooling/import_lint/bin/import_lint.dart`;
  5. `flutter test --reporter=failures-only` on the affected tests, then the
     full suite of each affected package (`dart test` fails here under
     `resolution: workspace`).
  A batch that changes only `docs/*.md` skips 2-5 (nothing compiled
  changed) and checks with `git diff --name-only` that it touched nothing
  else.
- **Commit** with explicit file names (`git add -- $MOD $NEW`,
  `git rm --cached -- $DEL`). Never `git add -A`. A re-run that finds nothing
  to commit says so and ends cleanly. Never push: pushing needs the owner's
  permission every session.

## 3. Tests

A test goes through the feature's real entry point: the adapter the
composition root wires, the real `AppTheme`, the real screen with its
providers overridden. A test that only checks a file exists, or that bypasses
the faulty function, reveals nothing.

- **The test must see what it tests.** A `ListView` builds only what is on
  screen: make the view tall enough, and prove the list's last item is built
  before any `findsNothing`.
- **Tap the widget that handles the tap.** A key on a full-width wrapper
  (an `Align` around a button) makes `tap` hit the empty middle; put the key
  on the button.
- **No real clock near a boundary.** A screen that picks "today" gets a
  fixed clock (an optional `now` parameter, as `RiyadhDayTurnover`). A test
  that places several kickoffs relative to `DateTime.now()` failed at 00:03
  when they fell on either side of midnight.
- **A `ListTile` on a card** sits in `Material(type:
  MaterialType.transparency)`: a card's colour hides its ink, and Flutter
  asserts.
- **Large text:** the UI survey (`ui_audit_survey_test.dart`) checks every
  screen at text x2 on a 360px phone with a zero baseline, but draws it
  with its own (often empty) data. A screen whose rows appear only with
  data gets its own test at 360px and text x2. Text in a `Row` is
  `Expanded` or `Flexible`.
- **Fix the class, not the instance.** Before sending a fix for a wrong
  pattern, grep for every copy of it (`grep -rn "ListTile(" ...`) and fix or
  clear each one.

## 4. Before sending

- Build a copy that matches the device: the uploaded tree, plus every batch
  sent since, plus the rewraps `dart format` made to them. Apply the patch to
  it **twice** (the second run must skip everything).
- Run the whole script on a git copy with stub `dart`/`flutter` binaries
  (the stub `flutter` also touches l10n, as the real one does): the success
  path, a re-run, and a forced failure at analyze, at the affected tests and
  at the full suite, to prove the rollback leaves a clean tree each time.
  Also the guards: dirty l10n, dirty tracked files, a missing earlier batch.
- Validate any YAML or JSON the patch touches or produces.
- State plainly what could not be tested (for example: no Dart SDK in the
  assistant's sandbox, so analysis and tests run only on the device).

## 5. Rules

- No placeholders, no TODOs, no mocks in production code.
- No new dependency and no architectural change without the owner's approval.
- A migration is additive only: no deletion of any user, account, points,
  fixture or prediction.
- A migration records itself as its last statement, inside its own
  transaction: `insert into ops.applied_migrations (version) values
  ('NNNN_name') on conflict (version) do nothing;` (the file name without
  `.sql`; table from 0081). `.github/workflows/migration-drift.yml` fails
  when the live database lacks a migration the repository has.

## 6. The reply

Arabic, short. Show only the changed lines, under each file name. Then the
run command:

```bash
f="$(ls -t /sdcard/Download/NN_short_name*.sh | head -1)"; echo "using: $f"; cp "$f" ~/fix.sh && cd ~/nukhbaa-backup-1787537565 && bash ~/fix.sh
```

And the command that reads a failure from the log, without the stack
frames, so the owner can paste it back as text:

```bash
grep -a -A4 -E "\[E\]|gained|The following .* was thrown" "$(ls -t /sdcard/Download/NN_short_name_*.log | head -1)" | grep -av -E "^#[0-9]|asynchronous suspension" | head -40
```

A failure is diagnosed from that text, never guessed from the end of a
stack trace: the lines above `Some tests failed.` are often ordinary logs
of a test that passed.

After `DONE`, the owner pushes with `git push origin main` (Northflank
redeploys the server; CI builds the APK, installed through the in-app OTA
update).

## 7. Reference skeleton

`42_admin_home.sh` (2026-10-08) is the full form: log, guards, rollback,
deletions. Its shape:

```bash
#!/usr/bin/env bash
set -Eeuo pipefail
NAME=NN_short_name
REPO="${NK_REPO:-/home/dev/nukhbaa-backup-1787537565}"
LOGDIR="${NK_LOGDIR:-/sdcard/Download}"
STEP=start; step() { STEP="$1"; echo; echo "== [$STEP]"; }
LOG="$LOGDIR/${NAME}_$(date +%Y%m%d_%H%M%S).log"
exec > >(tee -a "$LOG") 2>&1
trap 'echo "FAILED at step: $STEP (nothing was changed). log: $LOG"' ERR

step guards
[ "$(whoami)" = "dev" ] || { echo "STOP: run as dev"; exit 1; }
cd "$REPO"
[ -f pubspec.yaml ] && [ -f docs/project-context.md ] || { echo "STOP: not the repo root"; exit 1; }
[ -z "$(git status --porcelain -- apps/mobile/lib/l10n/)" ] || { echo "STOP: l10n has local changes (explain, do not discard)"; exit 1; }
[ -z "$(git status --porcelain --untracked-files=no)" ] || { echo "STOP: uncommitted changes"; exit 1; }

MOD="path/to/changed_file.dart"
NEW="path/to/new_file.dart"
rollback() {
  trap - ERR; cd "$REPO"
  for f in $MOD $NEW; do git reset -q HEAD -- "$f" 2>/dev/null || true; done
  git checkout HEAD -- $MOD 2>/dev/null || true
  rm -f $NEW
  git checkout -- apps/mobile/lib/l10n/ 2>/dev/null || true
  echo "FAILED at step: $STEP; tree restored, nothing committed. log: $LOG"; exit 1
}
trap rollback ERR

step patch
PATCH="$(mktemp)"
PATCH_B64='...one line of base64...'
printf '%s' "$PATCH_B64" | base64 -d > "$PATCH"
python3 "$PATCH"; rm -f "$PATCH"

step format;  dart format $MOD $NEW
step analyze; dart analyze --fatal-warnings .
step lint;    dart run tooling/import_lint/bin/import_lint.dart
step tests
cd apps/mobile
flutter test --reporter=failures-only test/path/to/new_test.dart
flutter test --reporter=failures-only
cd "$REPO"
[ -z "$(git status --porcelain -- apps/mobile/lib/l10n/)" ] || git checkout -- apps/mobile/lib/l10n/

step commit
git add -- $MOD $NEW
git diff --cached --quiet || git commit -m "type(scope): what changed and why"
trap - ERR
echo "DONE. nothing pushed. log: $LOG"
```
